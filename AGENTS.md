# AGENTS.md

Instructions for coding agents working in this repository. `CLAUDE.md` imports this file.

## What this is

Astro EdgeKits Core is a starter for internationalized Astro sites on Cloudflare Workers, built
on the npm package `@edgekits/astro-i18n`: translations live in Workers KV, each namespace is
cached at the edge and purged on change, translation keys are typed from the default locale's
JSON, and a middleware routes `/<locale>/...`. The engine is the package; this repository holds a
small site that uses it (five locales, a landing page, a blog on a content collection, a newsletter
form, RSS, sitemap, `llms.txt`, hreflang, a language switcher with flags).

Stack: Astro 7 (`output: 'server'`), `@astrojs/cloudflare` 14, wrangler 4, TypeScript,
Tailwind CSS. Node runs the build and the CLI; workerd runs the site.

Branches: `main` is the zero-JS variant (no UI framework, no hydration); `react-islands` is
`main` plus one commit that adds React and replaces the newsletter form with a react-hook-form island. `v1-version-based-cache`
and `v2-purging-cache` are archives of the architectures described in the EdgeKits article series;
do not change them.

## i18n: use the skill, not memory

Any task that touches localization (locales, namespaces, keys or copy, routing, the switcher or
banner, localized forms, hreflang, sitemap or RSS locale handling) starts by loading the
`astro-i18n` skill and follows it. The skill ships as the Claude Code plugin `astro-i18n@edgekits`,
enabled for this project in `.claude/settings.json`; other agents use its text in
`node_modules/@edgekits/astro-i18n/README.md` ("Using the skill") and the package README.
Do not copy engine code into `src/`: if the package lacks something, say so.

## Layout

- `edgekits-i18n.config.ts`: locales (lowercase codes, `countryCode` for the flag), default
  locale, namespaces, KV binding, cache settings. The single source of locale truth.
- `locales/<locale>/<namespace>.json`: translations. The default locale's JSON defines the schema;
  add a key there first.
- `src/pages/[lang]/`: every page lives under the locale segment. `robots.txt`, the sitemap and
  `public/` stay at the root. The middleware renders the default locale at the root by an
  internal rewrite; there is no root `index.astro`.
- Routing mode `prefix-except-default` (`en` at `/`, the others under `/<locale>/`): build every
  URL with `localizedPath` and `pathOptions` (`src/lib/paths.ts`), never by hand.
- `src/middleware.ts`: the package's `i18nMiddleware` runs first; project middleware follows.
- Generated by the CLI, never edited by hand, committed: `i18n-data.json`,
  `src/i18n.generated.d.ts`, `src/i18n/runtime-constants.ts`, `src/i18n/fallbacks.generated.ts`.
  `.i18n-hashes.json` is written only by `edgekits-i18n migrate` (production); it appears after
  the first migration and is committed from then on.
- `wrangler.jsonc` carries placeholder KV ids (32 hex characters): local development needs no
  Cloudflare account. Real ids and the purge token belong to the user's own deployment
  (`.dev.vars.example` lists the variables).

## Commands

```sh
npm run dev            # local dev server (reads local KV from .wrangler/)
npm run build          # astro check + astro build
npm run i18n:bundle    # regenerate the generated files, no KV
npm run i18n:seed      # bundle + push to LOCAL KV (run after every JSON edit)
npm run i18n:migrate   # bundle + push to production KV + purge (the user's, needs real ids)
npm run typegen        # wrangler types -> worker-configuration.d.ts
npm run format         # prettier --write
npm run format:check
```

After any change under `locales/`: `npm run i18n:seed`, then `npm run build`, then commit the
JSON and the regenerated files together.

## Invariants

- `main` ships no client-side framework and no hydration directives. The only form is the
  newsletter signup: an `.astro` form over an Astro Action (demo mode: validates and
  answers, stores nothing) with the vanilla `enhanceForm` controller from the skill's form recipe
  (project code under `src/`);
  validation errors are codes resolved through the `messages` namespace. React belongs to the
  `react-islands` branch only.
- Locale codes are lowercase everywhere (`pt-br`); only `toIetfTag()` upper-cases the region, for
  `<html lang>` and hreflang.
- The dictionaries are complete in all five locales; the missing-translation banner and the
  fallback are demonstrated by the blog: one post exists only in `en` and `de`. The index lists
  it in every locale (flagged as untranslated, with the banner on the list); in the other three
  locales the post page renders the English post with the banner and a `rel=canonical` pointing
  at the English URL, no `noindex` (edgekits.dev ADR-0017). Do not "fix" it by translating it.
- Flags are static SVGs in `public/flags/<countryCode>.svg` rendered with `<img>`; never inline
  them into the HTML.
- `@edgekits/astro-i18n/runtime` and `/middleware` are workerd-only: never import them from
  `astro.config`, `edgekits-i18n.config.ts`, or anything Node loads.
- Secrets (`.dev.vars`, `.env*`, tokens) never enter git. Stage files by name, not `git add -A`.
- The build must pass with zero `astro check` errors; Prettier runs before every commit.
